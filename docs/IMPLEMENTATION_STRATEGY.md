## 主线与依赖

Provider 是持续推进的主线，当前强制接管切片只按冻结范围收尾，不持续吸收相邻恢复场景。共享文件所有权允许时并行资产归集与 Afternic；设备切片完成后开发力量转向市场客户旅程。先完成能验证真实用户价值的纵向闭环，再扩展同类平台。恢复、平台和设备授权按实际依赖推进；
不把所有注册商写能力、整个旧阶段或通用框架全部完成设成 Afternic 旅程的前置。

## 平台与批量执行方案

1. **按能力取得协议证据。** 已确认官方能力使用官方 API；当前其余缺口直接开发私有 HTTP 适配。
   私有端点必须来自当前账户正常流程的证据，记录版本、请求语义与脱敏夹具。不得猜 URL、照搬历史社区代码，
   也不反复搜索官方文档来推迟实施。真实账号或登录挑战缺失时列出精确需求，继续其他不依赖它的工作。
2. **接续持久模型。** 同平台统一连接、角色和凭据代次；Listing 绑定已包含连接与资源身份，保持每个域名/连接一个当前绑定。
   资产以 canonical 域名关联，Registrar/DNS/市场观察与用户目标价分别保存。完整分页与扫描完成状态要可辨认，
   部分失败、空结果或过期观察不能触发资产清空。
3. **用真实切片确定复用面。** 从已有 Cloudflare 模式和 Afternic 所需能力实现目的明确的运输、解析与 custody；
   第二个平台验证复用边界。不先创建十二个空 Service，也不新建通用 Provider 代理或工作流引擎。
4. **operations 持有父计划。** 计划固定域名、平台、动作、价格与验证 DNS 范围，一次非资金确认覆盖独立步骤。
   后生成的 challenge 只能填充预先批准的范围。每步检查当前授权、连接代次、绑定、计划版本与平台前置条件。
5. **持久化执行与对账。** 复用 plan/attempt/result；发送前记录尝试，未知结果进入对账，成功后记录事实。
   休眠/退出不假定远端任务取消；重开先查 job、Listing、DNS 与 owner 状态，再决定续作。平台无幂等键时也不能
   用自动重发冒充 exactly-once。验证受理、HTTP 200、公共市场记录都不等于 owner 验证成功。
6. **DNS 变更有界。** 仅修改本计划需要且已批准的记录，保留用户及其他任务的记录，处理异步传播与冲突。
   全量覆盖式平台接口在 Service 内通过读现状、构造合并结果和前后复核实现业务上的最小变更；不能盲覆盖。
7. **真实资格与客户入口一起收口。** 扩展 manifest 和读取合同以表达有证据的可执行能力，完成 Native、IPC、UI 与
   平台验证后登记资格。清空拒绝分支、开放开关或只增加 manifest 条目都不是功能交付。

## 恢复方案

独立备份与活动库替换有不同依赖，分开交付和验证。独立备份优先满足用户的实际迁机场景：
用户手动选择本地文件位置，恢复最近一次备份；不增加备份调度、RPO 平台或 NAS 服务。

新格式使用独立版本及用户保管的恢复材料，不把旧安装 KEK 装入工件。实施时在 ADR-0023 的拥有边界内明确
加密套件、密钥生成/包装、材料编码与校验、认证元数据、流式大小上限和原生输入合同，并做负向验证。
优先评估高熵随机恢复材料；若选择人类口令，另明确抗离线猜测的 KDF、资源上限与恢复体验，不能静默降低强度。

先把工件认证并恢复为隔离的加密数据集，只提供受控查看与导出；不挂载 Active 授权、不生成 Outbox、不执行任务。
这个入口不需要旧安装防回滚 anchor，也不依赖登录或付费。随后实现有当前授权的差异预览和导入，以新 mutation
纳入活动工作区；任务历史不恢复成队列，缺失实体只有明确确认才删除，平台凭据重新连接。

云恢复使用最后成功同步的白名单副本和目标设备自己的 SQLCipher/key custody。新机恢复不要求丢失设备 drain，
但须完成强制接管的服务器权威与期限。活动库发布仍需 ADR-0023 的稳定 handle、create-only custody、独立 anchor、
安全数据库身份及故障证据；不能把测试协议改成生产开关。Windows 与 macOS 缺失的原生实现需直接列为交付项。

## 授权与运营方案

Standby 协议、Cloud 签发、独立签名用途、Host 验证、路由清单和降级必须作为相互匹配的合同交付。
只有 schema 与向量不能开放无 Lease 登录。重点验证 pending epoch 禁止登录分配、Grant 重放、错用途签名、
跨租户、撤销以及 Active→Standby 的原子停写。强制接管后的未同步旧库保留只读，并与新建云副本分离。

平台运行只在本机进行，Cloud 继续承担身份、设备、商业与副本。商业工作从现有 Licensing 的缺口出发，
让价格、计划、优惠和 Provider 映射可验证、可审计、可回滚；不向 Native 写死当前价格，不另建推测性的规则引擎。

## 执行与验收

- 每个切片交付合同、迁移/所有者、Native/Cloud 适配、客户入口及对应文档；边界变化更新拥有主题 ADR。
- 有意义的模块测试覆盖正向和失败边界；数据库行为运行相应 PostgreSQL/SQLCipher 测试；仓库整合运行 `pnpm check`。
  原生构件、真实平台和客户发行分别取证，不能用 Linux 测试或 fixture 代表 Windows/macOS 已通过。
- Windows/macOS 交叉备份恢复、断网后的未知结果、进程崩溃、重启续作、授权到期与凭据撤销都进入旅程验收。
- 可并行的是拥有模块明确且合同已对齐的工作；公开导出、迁移目录、composition root 和共享状态由整合者串行修改。
- 账号、硬件或真实环境缺失只阻塞依赖它的验证项；记录缺什么、需要怎样获得、下一步是什么，继续独立实现。
  不把暂不可验证改写为永久不支持，也不宣称已经完成。
- 运行时现状只更新 [当前实现](CURRENT_IMPLEMENTATION.md)，具体进度和证据记入
  [执行台账](phase0/PHASE0_EXECUTION_PLAN.md)。旧路线图阶段不是新的技术前置；不在 ADR 中重新堆积历史日志。
