# ADR-0003：账号门禁、双设备与用户触发的 WebDAV 数据交换

状态：Superseded by ADR-0004 and ADR-0005  
日期：2026-07-30

> 本文保留为历史决策记录。当前同步与设备方案以 ADR-0004、ADR-0005 和 ACCOUNT_AND_SYNC.md 为准。

## 背景

GoodDealer 按月、年和终身 License 销售，需要账号登录、授权刷新和设备名额管理。用户希望一个账号绑定两台设备，并能借助 WebDAV 完成备份迁移或后续同步，同时不把域名资产和平台凭据托管给 GoodDealer。

直接通过 WebDAV 同步 SQLite/SQLCipher、WAL 或整个应用数据目录会产生并发写入、文件锁、WAL 不一致、Schema 差异和密文回滚风险，不适合作为跨设备协议。

## 决策

- 主界面之前设置账号和 License 门禁；记住登录时可用 OS Keychain 中的凭证静默恢复会话。
- 一个账号最多绑定两台设备。
- 账号控制面仅处理身份、订单、授权、设备绑定和更新元数据，不接收域名业务数据。
- License 过期且离线宽限结束后不允许进入主界面，也不提供只读或紧急操作例外；本地数据不删除。
- 终身 License 包含所有未来大版本。
- 账号会话、有限期 Offline Device Lease 与 Entitlement 分离；终身 Entitlement 永久，但设备 Lease 仍需偶尔联网免费续签。
- 备份、迁移和设备间数据交换只能由用户主动触发。
- 首版 WebDAV 只传输端到端加密的一致性备份与加密 Manifest。
- 禁止同步活跃数据库文件。两份完整备份分叉时拒绝静默覆盖，不在 V1 自动合并。
- 后续双设备合并采用不可变加密 Change Bundle、ETag/CAS 和字段级冲突处理，仍由用户主动触发。

## 结果

优点：

- 商业授权、账号登录和两设备限制可以统一执行。
- GoodDealer 服务端不形成域名资产和密钥的集中风险。
- 用户可选择自己的 WebDAV 服务，备份提供商只能看到密文。
- 避免网盘文件级同步破坏本地数据库。

代价：

- 账号和授权服务不可用时只能依赖 Offline Device Lease 的剩余期限；终身权益也不能绕过账号与设备门禁。
- V1 两台设备不能同时编辑后自动合并，用户需要执行明确的交接流程。
- License 过期会阻断用户查看本地资产，这是明确的商业产品决策。
- 后续 Change Bundle 需要独立的冲突、加密、重放和版本兼容协议。

当前协议见 [账号、设备与云同步](../ACCOUNT_AND_SYNC.md)。

## 后续决策

2026-07-31 决定由 GoodDealer 服务端默认同步可读的域名业务数据，本 ADR 关于账号门禁和双设备名额的结论继续有效；关于 WebDAV 作为主要多设备数据交换方案的结论由 [ADR-0004](0004-cloud-business-data-sync.md) 取代。随后进一步决定从现行产品范围删除 WebDAV 集成，只保留本地加密备份文件导出/恢复；本文仅用于保存历史讨论。
