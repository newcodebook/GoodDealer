# ADR-0001：采用本地执行的 Tauri 客户端

状态：Accepted, amended by ADR-0004 and ADR-0005  
日期：2026-07-30
修订日期：2026-07-31

## 背景

GoodDealer 需要访问域名注册商、DNS 服务和销售平台的高权限 API。若服务端集中保存这些操作凭据，一旦服务端、员工权限或供应链被攻破，影响可能涉及域名解析、转移和销售。

产品计划优先发布 Windows 与 macOS，后续支持 iOS 与 Android，并通过月付、年付和终身 License 销售。

## 决策

采用 Tauri 2 + TypeScript 的本地执行客户端架构，并按 ADR-0004 增加云端业务数据同步、按 ADR-0005 增加单执行设备协调和 Standby 云端只读能力。

- 域名、价格、业务状态和脱敏记录强制同步到服务端，服务端可以读取。
- API Key、OAuth Token、Cookie、Auth Code、Browser Profile 和数据库密钥仅存于用户设备。
- TypeScript 实现 UI、应用用例、领域逻辑和连接器映射。
- Rust/Tauri Host 实现本地数据库、系统密钥库、受控网络、文件、更新和 License 安全边界。
- 远程服务负责账号、License、最多两台设备绑定、单执行设备协调、Standby 只读授权、业务数据同步和更新元数据。
- 首版使用编译期连接器，不支持未签名的运行时插件。
- 数据库主密钥同时支持 OS Keychain 与用户离线 Recovery Secret 恢复。
- 产品只提供用户主动操作的本地加密备份文件导出/恢复，不集成第三方远程备份服务，也不同步活跃数据库文件。

## 结果

优点：

- 避免集中保存能够直接控制平台的密钥。
- 当前活动设备可在签名离线许可内访问和整理数据，并继续平台操作最多 24 小时。
- 两台绑定设备都可查看云端业务数据，但任意时刻只有一台可以修改业务状态、配置本地平台凭据、批准并执行操作。
- Tauri 可为未来移动端提供共享基础。

代价：

- 服务端可以读取域名清单、成本、价格和状态，需要承担隐私与数据泄露责任。
- 设备交接需要云端 Schema、ActiveDeviceLease、Lease Epoch 和恢复候选。
- 数据迁移、备份、数据库升级必须在本地可靠完成。
- Windows、macOS、iOS 和 Android 的密钥库、后台任务与签名发布均需单独测试。
- License 需要兼顾离线使用与商业保护。

## 不采用的方案

### 云端平台凭据托管

不采用。集中保存域名平台密钥造成不可接受的资产安全和责任风险；保存普通域名业务数据则由 ADR-0004 明确采用。

### Electron

暂不采用。Tauri 的原生安全能力、包体和未来移动端支持更符合当前方向。

### 纯 TypeScript/浏览器实现

不采用。浏览器环境无法提供足够可靠的系统密钥库、受控网络和本地加密数据库边界。

### 运行时第三方插件

首版不采用。插件需要访问高权限密钥和网络，签名、沙箱与兼容成本过高。
