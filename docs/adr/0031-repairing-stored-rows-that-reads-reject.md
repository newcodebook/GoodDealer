# ADR-0031：修复让读取失败关闭的存储坏行

状态：Accepted — 产品负责人于 2026-11-16 采用台账第 106 行的建议方案：复制的业务数据以新的变更修复，
保持副本收敛；已确认的 Outbox 历史保持不可变，只标记、不改写。本文把该方案落到现有各类坏行上。
已实现：R1、R2 均已交付（见文末“实施”）；第 3 节的全表校验移除另作变更。

## 背景

读取对存储行逐行校验并失败关闭（AGENTS.md：不可信边界从 `unknown` 校验、失败拒绝）。迁移前写入的
少数坏行因此可以让整页长期不可读。设置“关于”已经按读取分类报告这些行的数量（台账第 155 行），
但还没有修复入口：

| 设置计数 | 存储位置 | 受影响的读取 | 行的性质 |
| --- | --- | --- | --- |
| `malformedExpiries` | `domain_assets.expires_on` | 资产库、续费 | 本地生命周期字段，不进 wire，不复制 |
| `invalidRegistrarObservations` | `registrar_observations` | 续费（变慢，显示时失败） | Provider 观察证据，本地，表禁止更新与删除 |
| `rejectedDnsRows` | `domain_asset_provider_bindings`、`dns_zone_observations` | DNS 健康 | 本地绑定（身份不可变、禁止删除）与观察证据 |
| `rejectedListings` | `marketplace_listing_observations` | 销售 | Provider 观察证据，本地 |
| `malformedOutboxRows` | `sync_outbox.created_at` | 历史 | 本设备的变更流水；已认领后不可删除，已确认的是同步历史 |

存储完整性迁移已在写入时拒绝新的此类行（到期日期、绑定平台一致性、Outbox 时间），所以这里只处理
迁移前留下的行。Provider 账号、绑定与观察不同步（ROADMAP S1），四个同步字段（`note`、
`portfolioId`、`tags`、`targetPrice`）写入时已校验，目前没有已知坏行。

## 决策

### 1. 按数据性质选择修复方式

- **复制的业务数据**（同步字段）：只通过本设备一次普通的本地编辑修复——写 Outbox 行、经 Cloud
  ingest、由其他副本经 Inbox 应用——不做只改本地的改写，否则副本分叉。今后若发现这类坏行，修复入口
  生成的就是这样一次编辑，服从 Active Lease、generation 与冲突规则。
- **已确认的 Outbox 历史**（`acknowledged`，以及已终止的 `rejected`/`conflicted` 证据行）：不改写、不删除。
  修复写入一条标记，历史读取据此把该行的提交时间显示为“时间无效”，其余列照常校验。未确认的行同样
  只标记：其 wire 已冻结，改写时间会让同一 mutation 有两个版本。
- **不可变的 Provider 观察证据**：不改写、不删除。修复写入隔离标记，读取把被隔离的观察视为没有可用
  观察：注册商名称显示为未知、Zone 显示为未观察、该市场不显示挂牌；更早的观察不顶替它（它描述的是
  平台已离开的状态）。下一次成功的观察照常取代它。
- **本地且不复制的可变字段**（`domain_assets.expires_on`）：改写为 `NULL`（“到期未知”），由下一次
  注册商观察重新写入。它不在 wire 中，改写不会让副本分叉。
- **本地绑定**：不删除、不改身份（两者都由触发器禁止）；修复隔离无效绑定，读取把它视为没有绑定。
  隔离的绑定仍占据该资产的 Zone 绑定位置，所以在本 ADR 范围内不能在其上重新绑定；需要时另行决定。
  绑定行校验也包括它所经由的连接（平台一致、连接名称有效）；连接名称无效时，经该连接的每个绑定都会
  逐一被隔离。隔离一个非 Cloudflare 的活绑定后，该资产此前不参与校验的 Cloudflare 观察开始参与；
  若它也无效，计数在修复后仍不为 0，再执行一次修复即可。

### 2. 修复是用户发起的、可审计的本地事务

- 入口在设置“关于”的计数旁，每类一个“修复”动作；不在启动或后台自动执行，因为它会让某些值变为
  未知或不可用，用户应先看到将受影响的数量。
- Host 命令在一个 IMMEDIATE 事务中用与读取相同的校验谓词重新选出坏行，只处理这些行；计数为 0 时
  幂等返回。Renderer 只发送类别，不发送行标识或值。
- 每处理一行写一条不可变修复回执：类别、行键、原值的 SHA-256（原值本身不复制进回执，避免把坏数据
  扩散到新表），以及修复时间。回执不进 wire、不进备份白名单以外的位置。
- 修复不需要也不使用任何凭据。

### 3. 读取侧全表校验何时移除

修复与回执交付后，读取跳过已隔离、已标记或已解除的行，其余行照旧失败关闭；所以修复前读取的行为
不变，修复后整页恢复可读。只有同时满足以下两点时，才能移除对应读取的全表校验：写入侧触发器拒绝
该类新坏行（已满足）；迁移在升级时确认该类未修复行数为 0，否则保留校验。移除另作变更记录在本 ADR。

## 后果

- 单行坏数据不再让一页永久不可读，且修复不改写任何已同步历史或观察证据。
- 修复让少数值变为未知（到期日期）或不可用（观察），直到下一次 Provider 观察；这是有意的，因为
  坏值本身不可信。
- 新增本地 schema：修复回执表（同时充当观察与绑定的隔离标记，R1）与 Outbox 时间标记（R2），各需前向迁移与 schema guard 更新。

## 未采用的方案

- **直接删除或改写坏行**：观察与 Outbox 证据不可变是审计依据，删除会让绑定的 `ON DELETE RESTRICT`
  证据链断裂，改写已确认的 Outbox 时间会让同一 mutation 有两份历史。
- **读取跳过坏行而不修复**：静默隐藏数据，违反失败关闭。
- **启动时自动修复**：用户看不到哪些值将变为未知。

## 实施

- **R1（已实现）**：本地迁移 `202611160002`（active-workspace/storage-repair）新增不可变的
  `storage_repair_receipts`（类别、行键、原值 SHA-256、修复时间；只能指名现存行），它同时是读取遵循的
  标记；隔离挂牌递增 `sales_listing_generation`，使缓存的销售台失效。到期日期、注册商观察、DNS 行
  （绑定与观察分别判定、只隔离失败的部分）与挂牌四类修复复用设置计数与读取的同一校验谓词，在一个
  IMMEDIATE 事务中执行，Host 提交栅栏在提交前最后检查。Host 命令 `repair_stored_rows` 接受
  `{schemaVersion: 1, expectedReadGeneration, repairKind}`（`deny_unknown_fields`，类别取设置计数名，
  未知类别与过期 read generation 一律拒绝；`malformedOutboxRows` 在 R1 中拒绝，R2 起接受）；有修复时推进 read generation。
  资产库与域名详情的注册商名称、资产库的挂牌计数与续费、销售遵循同一隔离。
  测试：四类修复各清除自己的计数、回执逐行、重复执行为 0、被栅栏拒绝时零写入、读取恢复且被隔离者
  按上文显示（含资产库、域名详情与挂牌计数）、Zone 观察单独被隔离且 DNS 计数随之一致、回执不可改不可删且不能预先指名不存在的行、隔离最新挂牌不由更早挂牌顶替、Host 拒绝
  多余字段/未知类别/过期 generation 与移动的栅栏。
- **R2（已实现）**：本地迁移 `202611160003`（active-workspace/outbox-commit-time-marks）新增不可变的
  `sync_outbox_commit_time_marks`（mutation、原 `created_at` 的 SHA-256、标记时间；插入触发器要求该 Outbox
  行存在且 `created_at` 非规范）。`malformedOutboxRows` 修复只写标记，不改写任何 Outbox 行；历史读取与设置
  计数跳过已标记行的时间校验，历史合同的 `committedAt`（及历史条目的 `occurredAt`）变为可空，界面显示
  “时间无效”。Tauri 命令 `local_storage_repair`（能力 `allow-local-storage-repair`）只转发
  `{schemaVersion, expectedReadGeneration, repairKind}`；client-core 的请求与回执合同严格校验，回执必须回答所请求的
  类别。设置“关于”在可写工作区为每个非零类别提供“修复”，确认对话框写明数量、该类修复的效果与回执只存摘要；
  无论成功与否都重新读取计数，成功时刷新工作区发布（read generation 已推进）；只读或没有 Host 命令时不提供
  修复并说明原因。测试：Outbox 标记清零计数、重复为 0、历史以空时间读出、原时间不变、对规范行插入标记与删除
  标记被拒；适配器只发送三字段并拒绝多余字段/未知类别/错配回执；面板只在可修复时显示按钮、确认框的数量与效果、
  执行中锁定。
- **第 3 节的移除条件**不因 R1/R2 改变：本 ADR 范围内不移除任何读取侧全表校验；修复前读取行为不变。
