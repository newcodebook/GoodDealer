# ADR-0013：账户激活时创建个人默认工作区

状态：Accepted product architecture; customer onboarding is not currently composed.

## 决策

`Account` 是身份和商业范围，`Workspace` 是业务资料的租户边界。账户完成验证并激活时，
identity/workspace 组合必须在一个服务器事务中创建：

- 一个不可变 ID 的 Account；
- 一个不可变 ID 的个人默认 Workspace；
- 该 Account 对该 Workspace 的唯一所有者绑定。

首发产品只支持这个账户拥有的一个个人工作区。它不提供邀请、团队成员、工作区创建、
工作区切换、所有权转移或将账户数据并入其他账户工作区的行为。商业授权和账户安全事实
保持 Account 范围；资产、同步变更、游标、投影和审计工作区记录保持 `(accountId, workspaceId)`
租户范围。

客户端只提交经协议定义的业务意图。会话主体、默认所有者绑定和工作区范围必须由服务器端
解析；客户端、缓存、UI 或请求参数都不能选择、伪造或扩大租户范围。

## 理由

个人域名资产管理首发不需要团队协作，却必须从第一条业务记录开始具备稳定的工作区隔离。
自动创建默认工作区消除首次使用时“无范围”状态，保留不可变 `workspaceId`，同时避免为未
交付的成员和多工作区功能预置角色、兼容层或宽泛授权。

## 后果

账户激活、默认工作区创建和初始工作区记录必须原子完成，并且任一失败都不产生半成品
业务路径。所有 Workspace 数据面入口必须在访问数据前验证服务器导出的绑定。

未来的多工作区、协作成员或所有权转移不是本决策的隐含扩展；如需加入，必须先通过新的
ADR 定义身份、成员、商业归属、迁移和租户授权模型。

## 当前实现

Cloud 尚未组合客户账户或工作区路由，Desktop 也未连接业务渲染。本 ADR 定义后续实现
目标，不声明账户创建或工作区访问已经可用。
