# GoodDealer 浏览器自动化

## 适用范围

首发产品明确不包含嵌入式浏览器或浏览器自动化。当前浏览器自动化不可用；本文件同时保留
未来若重新立项时必须遵守的安全约束，不能被读作可执行产品能力。

## 首发决定

首发不创建或控制远程页面、Browser Profile、Cookie、密码输入、多因素认证、DOM、脚本、
弹窗、下载或上传，也不以浏览器作为任一 API 的回退。需要网页操作时，界面只能显示脱敏的
人工步骤和结果要求，由用户在 GoodDealer 之外的浏览器自行完成。

任何未来浏览器能力必须先有新的 ADR，并逐项明确提供商条款、页面流程、WebView 平台矩阵、
IPC/权限、秘密边界和独立审查。详见
[ADR-0017](adr/0017-v1-excludes-browser-automation.md)。

## 已接受的目标约束

若未来增加浏览器能力，必须满足以下规则：

- 远程页面与本地应用展示域及受保护资源隔离，远程内容不能获得本地特权接口。
- 用户完成密码、多因素认证、挑战和其他身份步骤；软件不得绕过或代填这些步骤。
- 自动化仅处理明确、受限、可版本化的页面流程，不允许任意脚本或系统操作。
- 导航、弹窗、下载、上传、权限请求和结果回传都要由拥有模块在资源边界前失败关闭。
- 页面观察只是观察；任何外部结果都需独立、可验证的业务处理后才可影响产品资料。
- 未知页面、目标歧义、版本不兼容或授权不明确时必须停止并回到人工处理。

## 当前实现

`automation-host` 的公开引擎可用性只有 `Unavailable`。没有浏览器会话、远程页面桥接、
浏览器组合、提供商浏览器执行或浏览器结果路径。Tauri 的三个本地业务命令不包含浏览器、
Cookie、Profile、下载、上传或任意网络能力。

## 交付条件

未来功能需有明确产品范围、平台条款、具体最小权限设计、原生 WebView2/WKWebView 观察、
秘密泄漏控制、最终构件签名/归档和独立审查。源码、可移植测试、本地报告或视觉素材不
证明上述任何条件。
